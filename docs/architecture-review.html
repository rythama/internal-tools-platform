Renting the console, or owning it

Three internal tools today, ten more planned, $250K/year in platform licence. The question is not whether engineers can build a review queue — they obviously can. It is whether tool #11 stays cheap, and whether it can get the audit trail wrong.

What you are actually choosing between

Both systems put the same reviewer in front of the same case. The difference is not the screen — it is where the customer's tax ID comes to rest, who controls the record that says who looked at it, and what has to happen for the behaviour to change.

The invariant that makes it defensible

Owning the code only helps if the eleventh tool cannot quietly skip the controls the first one established. So the platform is built around a single structural property rather than a convention: there is no code path from the console to a domain table that does not write an audit row in the same transaction.

Not middleware, which can be forgotten. Not a logger, which can fail independently. One function, withAudit(), that commits the mutation and its audit record together or commits neither.

How tool #11 ships

This is where Devin earns its place, and also where the honest caveat lives. Agent speed collapses the build step and leaves the review step almost untouched. Any cost model that forgets this will overpromise.

What we are deliberately not replicating

Power Apps is not one product, it is three bundled capabilities. Only one of them is worth rebuilding, and being clear about the other two is the difference between a plan and a pitch.

CapabilityReplicate?Reasoning
Undifferentiated plumbing — auth, RBAC, tables, forms, audit, deploy yes Pure fixed cost. Paid once in packages/core, amortised across every tool. This is the entire opportunity.
Non-engineers building their own apps no Devin makes engineer-hours cheap; it does not turn an ops analyst into an app author. Different mechanism. Claiming otherwise oversells it, and the gap shows up as a ticket queue three months in.
1,000+ prebuilt connectors no Build the three or four integrations you actually use. Rebuilding a catalogue you don't need is how a platform project dies.
Vendor compliance posture partly A vendor's certifications never transfer to you — but they do shrink your evidence burden. Building moves that work in-house. Real cost, and it belongs in the model.
Escape hatch to arbitrary code only here The one capability a low-code platform structurally cannot offer. A tool that outgrows the spec drops into React against the same primitives instead of hitting a ceiling.

Prototype built in roughly two hours with Devin as the implementation tool; architecture, schema, core contract and CI were authored by hand first, deliberately. Economic model and recommendation follow separately. SQLite stands in for Postgres so the repository runs with no infrastructure — a demo tradeoff, not a production recommendation.
